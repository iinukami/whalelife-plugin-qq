# WhaleLife QQ 插件

QQ 私聊接入，复用 WhaleLife 的模型配置、人格、会话与记忆。支持白名单、文字分段、图片理解、语音转写、图库收藏和发送。QQ 空间由独立仓库提供，本仓库不包含空间插件的工具、设置页、回执存储或自主行为。

WhaleLife 交流 QQ 群：**962935021**

0.19.0 新增供插件调用的统一视频分享服务 `sendVideoShare`。在 QQ 设置的「视频分享方式」中选择图文卡或小程序，默认图文卡：将封面、标题、描述和完整视频链接作为一条普通 QQ 图文消息发送。点击文字链接打开视频网页，图片本身不是可点击跳转的 ARK 卡片。封面获取失败时，在提交前改为发送完整文字链接；已经提交后不会补发。公开参数、回执和消费者迁移见 [视频分享契约](VIDEO-SHARING.md)。

选择小程序时，使用已有 QQ 连接请求 QQ 自身生成带签名卡片，并原样发送；手机端播放和「打开 B 站 App」仍有未解决的兼容问题。旧 `sendMiniAppShare` 始终发送小程序，不受新配置影响，具体边界见 [小程序分享契约](MINIAPP-SHARING.md)。B 站等消费者需要自行接入新 `videoShareApiVersion: '1.0.0'` 服务；仅升级 QQ 不会把旧消费者自动改成图文分享。

两种方式都只向白名单好友发送，要求调用会话及 QQ 配置均有完整权限。B 站消费者负责提供已验证视频的标题、封面与目标，QQ 不读取 B 站账号或数据，不接受任意 JSON，不调用第三方签名网站。QQ 不依赖 B 站、图库或冲浪插件；它们未安装或停用时仍可独立使用。

分享正文、封面字节和签名只在本次调用内使用，不写入发送计划、日志或记忆；持久回执仅保存指纹、投递状态及必要的格式标记，记忆只记录固定成功事实。新旧入口共用动作账本，相同动作 ID 不重发；同 ID 改格式或内容返回冲突，不能靠切换方式重试。取消、协议失败及结果不确定均不自动补发。平台消息 ID 只确认平台接收，不证明对端显示、播放或已读。

视频分享的封面准备或签名生成单独排队；准备好后进入原有发送队列，不插入一份回复的分段中间。实际发送前才关闭本轮收件入口，准备期间仍可合并连续来信。原有文字、图库、空间接口及用户数据保持不变。

从 0.20.0 起，收到的 B 站小程序、普通分享及 QQ 图文卡会提取视频链接和标题，作为用户来信进入当前会话；同一私聊中引用的卡片也可识别。QQ 只解析卡片，不联网打开视频、不下载封面、不调用识图；打开、字幕和观看继续由已安装的 B 站插件提供。未安装 B 站插件仍能收到链接，不影响普通 QQ 聊天，也不受「视频分享方式」这一发出设置影响。

只提取已知字段中的官方视频地址、b23 短链或固定视频页路径，去掉追踪参数；合法的 `p=1…100` 单独标明，`page` 不推测为分 P。标题限制长度并明确标为外部资料，不代表已观看。卡片原文、签名、封面和其他字段不会交给模型或保存到 QQ 收件账本；规范化后的链接和标题按普通来信处理。未知卡片保留不支持提示，不用卡片任意字段猜链接。升级不会重新处理以前收到的卡片，同 ID 内容冲突不会重发；可重新分享一条新消息。

## 配置与使用

从 0.17.0 起默认启用「回复前合并连续来信」，可在 QQ 设置关闭。支持轮内追加的宿主上，首条立即开始处理；同一账号、好友的后续消息在识别完成并获主干接纳后进入当前轮，保留各自消息 ID、时间和历史，共用一次最终回复。`qq_acknowledge` 提前接话不封口，正式文字或图片提交前封口；之后或本轮容量已满的消息等待下一轮，最终回复仍按现有正则分段。

追加不取消在途模型请求或已开始的工具，不重做已完成动作；主干在下一步结合补充重新判断，旧最终候选不会发送。图片/语音识别若晚于封口则进入下一轮；已经取得原图引用的消息保留引用绑定的会话，避免切换会话后失效。合并不跨好友，停止、失败或重载不自动重放。宿主缺少可选 `channel.openTurn` 时保留原来逐条回复，页面明确显示能力缺失；开启此能力需要 2026-11-08 轮内追加接口（主干提交 `ab9ba0b`），其他原有功能仍兼容最低宿主。

从 0.16.0 起，模型可用 `qq_acknowledge({text})` 在当前来信的耗时操作前简短接话，然后继续工具调用，最后由原渠道发送结果。入口从可信当前来信确定收件人和稳定动作 ID，无需额外查询联系人；最多 80 个字符，同一来信重复调用不会重新投递，不能换文字重试。接话沿用发送权限、白名单、分段、取消及临时资料规则，只确认消息发送，不代表业务操作完成。普通聊天直接回复，不插入固定文案或定时提示；是否接话、说什么由模型决定，插件无法保证模型每次都选择该工具。

首次安装默认关闭。进入插件设置选择人格和好友白名单，明确启用。只处理白名单好友私聊，不处理群消息或自身消息。

### 私聊语音条

从 0.23.0 起，语音插件可用现有的 `qq_say` 把合成的 WAV 直接发成私聊语音条。QQ 接入启用、具备完全执行权限且好友在白名单时可发送。语音合成和音色由调用方负责。桌面包使用随包 NapCat 转码，外部 OneBot 服务需要支持 `record` 语音段及 WAV 转码。

其他插件可检测 `qq.outboundVoiceApiVersion === '1.0.0'`，调用 `qq.sendMedia({ sessionId, userId, actionId, personaId, parts: [{ type: 'voice', id, mime: 'audio/wav', base64 }] }, { signal })`。一次发送一条独立语音，`id` 为 WAV 字节的 SHA-256 小写十六进制，`base64` 为不带前缀的编码。大小受 QQ 单项媒体限制及 25 MiB 上限约束。稳定的动作 ID 对应同一份音频；可用 `qq.mediaDelivery({ sessionId, userId, actionId })` 查回执。获得有效平台消息 ID 才确认发送，提交后结果未知时禁止重发。QQ 的回执记录只保存摘要、元数据与状态。

- Windows 桌面模式复用桌面 QQ 登录；首次使用需要本人完成登录/手机验证。不会修改 QQ 快捷方式。
- 外部模式连接已有 OneBot v11 服务，地址和令牌由用户配置。
- 对话模型沿用人格/主干选择；识图选择视觉模型，语音可用平台转写或 STT 模型。
- 从 0.20.1 起，看图未配置输出上限时默认 2048 token。在所选看图模型的“高级请求参数”设置 `{"max_tokens":8192}`，或使用服务支持的 `max_completion_tokens`；两者都填时后者优先，不同时发送两个字段。显式上限必须是正安全整数，非法值在请求前报错；不会覆盖已保存配置或修改思考开关。思考模型可按需要调高，2048 不保证适合所有任务。仅有思考或达到上限而无正文仍按识图失败处理，不自动重试或切模型；已有有效正文维持原处理。
- 当前主干上跟随 Web 当前会话；切换会话只影响下一轮，已开始的回复保留原会话。
- 图库是可选服务，缺失或故障不影响普通文字聊天。收藏/发送开关与 QQ 空间的开关独立。
- 失败或结果不确定的发送不会自动重放。重复消息及动作 ID 去重；既有用户数据升级时保留。

文字发送工具及 `qq.sendText` 保留原有 `status` 等字段，新增 `delivery`：`outcome` 为 `not_sent`（明确未发送）、`partial`（部分确认发送）、`unknown`（结果未知）或 `sent`；同时返回总段数、确认发送数、明确未发送数、未知数和未提交数。部分发送仍可能包含未知段，须一起判断。`scope=current_call` 仅表示本次调用在发送前被阻止，不推断以前同一动作的结果。发送确认不等于已读；未回复不能证明用户态度。

普通 QQ 自动回复未完整确认时，会通过宿主公开记忆接口记录最小投递事实，供后续对话区分“生成了回复”和“成功发出”；不保存额外正文或临时外部资料。回执/记忆保存失败不触发重发。旧版仅有 `failed` 的台账缺少发送阶段证据，保守标为未知；不会篡改旧记忆或自动补发旧消息。

支持临时工具的宿主上，浏览空间等临时资料后仍可调用 `qq_send_message`。QQ 只把“正文不留存”的固定摘要及指纹交给渠道去重，原文仅在当次投递使用；私有分段台账保留数量、状态和平台消息 ID，不存正文或分段计划。重复同 ID 返回既有回执，停用、重载或取消后不恢复原文、不补发剩余段，也不把摘要发到 QQ。普通发送行为不变；同一动作切换普通/临时模式会触发内容一致性检查并阻止重复发送，不应换 ID 绕过。

选择已登录桌面 QQ 时，短暂离线或不完整状态通知会暂停接入；收到完整状态并核验为原账号后恢复。检测到真正切换账号或组件初始化失败时保持阻止，避免使用另一身份操作。连接建立时及每 15 秒以只读好友列表检查原生接入是否可用，不把 WebSocket 心跳或缓存登录信息视为在线依据。协议错误仅显示固定诊断及错误码，不回显任意原始正文。

从 0.19.2 起，已接入的 QQ 重新启动后，刷新账号列表并重新连接同一账号，可以识别并恢复本插件留下的旧接入标记；账号、程序路径和旧进程记录必须核验一致。不会自动换号，也不会接管其他组件。

从 0.19.3 起，已选择的桌面 QQ 接入另行监听下线状态和原因，避免离线后的业务隔离同时遮蔽诊断。最近 32 条脱敏事件保存在本插件所选进程的 data/desktop-attach/<进程标识>/data/desktop-bridge/runtime/connection-diagnostics.json；只记录时间、状态/下线类型码、同设备标记及固定原因分类，不保存账号、提示原文或聊天内容。重复连接复用监听；写入失败不会改变收发与登录。已运行的旧接入可通过刷新账号列表并重新连接同一账号补上监听，无需退出 QQ。该版本不改变原生保护开关，不触发自动重登，也不代表已查明或修复所有账号失效原因。

从 0.14.1 及更早版本升级后，已运行的 QQ 进程仍持有旧接入代码。在 QQ 设置中刷新账号列表并连接原账号，即可原地更新恢复检查；不退出桌面 QQ、不重复加载 NapCat、不重放失败消息。普通插件停启仍复用原连接，不反复注入。

### QQ 空间与第三方组件

[QQ 空间](https://github.com/iinukami/whalelife-plugin-qzone) 单独安装到 QQ 的 `sub/qzone/`。QQ 仅提供账号所属的传输服务，空间业务由子插件负责；单独安装 QQ 不要求安装空间。

从 0.14.4 起提供可选 `qq.qzoneReferenceApiVersion = '1.0.0'` 和 `qq.qzoneReferenceStatus({sessionId, ref, expectedKind?}, {signal})`。`sessionId` 必须取可信工具会话，`expectedKind` 为 `post` 或 `cursor`。成功返回 `{valid:true,kind,expiresAt}`（毫秒时间戳）；失败返回 `{valid:false,reason,message}`。`reason` 为 `invalid_reference`、`unreadable_reference`、`offline`、`account_changed`、`session_mismatch`、`expired` 或 `wrong_kind`。诊断不访问网络，不返回原文、图片地址、账号或凭据，不延长原有 15 分钟有效期。无法解密可能是连接重载或引用损坏，不能据此认定实际过期。

从 0.15.0 起提供可选 `qq.qzoneVideoApiVersion = '1.0.0'` 和 `qq.qzoneReadVideo({sessionId, ref, index}, {signal})`，返回 `{mime:'video/mp4'|'video/webm', base64}`。调用方从可信工具会话取 `sessionId`，使用 `qzoneBrowse` 返回的本会话 `ref` 和 `0 <= index < videoCount`（最多 8 个）。浏览结果的 `hasVideo` 保留原语义，新增 `videoCount` 仅统计引用内支持的原始视频源；封面、第三方播放器和不支持的来源不会冒充可读取视频。

QQ 只在内存中读取经账号、会话、有效期校验的空间原生视频，不接受调用方提供 URL、路径或凭据。媒体固定来自 `photovideo.photo.qq.com` 的 MP4/WebM 地址，不携带空间 Cookie、不跟随重定向；单次最多 64 MiB、60 秒，同时只允许一次视频读取。取消、停用、账号变化或下载失败均不交付、不自动重试、不落盘。旧引用缺少视频来源时仍可用于原有功能，视频需要重新浏览。QQ 不解码或理解视频、不依赖视觉或图库插件；空间消费者按需把字节交给视觉公开服务，字节和签名地址不能返回模型或写入日志。

空间插件适配：在捕获原有引用错误时，检测此可选入口并查询诊断，将固定 `message` 作为当轮临时反馈；旧父插件继续用原错误兜底。旧浏览/读图/解析入口及其错误文本保持不变，因此无需同时升级。浏览、读图没有动作 ID，其一般失败提示应要求检查连接或重新浏览，不应要求“用原动作 ID 查回执”；点赞、评论、转发仍按已有动作回执核对，诊断不是重试授权。无需改动空间插件即可解除临时上下文中的 QQ 私聊限制。

此接口只反映查询当下的引用状态，不能倒推历史失败原因；若返回有效，空间插件仍须保留原失败，不能误报成功或自动重做互动。诊断结果也是当轮临时资料，不应记录完整引用或外部正文。

### 新安装与 NapCat 离线组件

Windows x64 普通用户使用本插件发行资产中的 `whalelife-plugin-qq-0.20.1-windows-x64.zip`：解压后将 `qq/` 放入宿主的 `plugins/`。桌面包已带经过固定 SHA-256 校验的 NapCat 4.18.41 Shell/Framework 和 Frida 原生绑定，安装后不需要访问 NapCat 上游下载地址；QQ 客户端仍由用户自行安装、登录。首次安装不要把整个源码仓库当作插件目录。

已有安装升级时，只更新发行清单中的程序文件，保留 `data/`、账号配置和独立安装的 `sub/qzone/`；不要删除整个正式插件目录。`BUILD.json` 记录本包自己的文件摘要，不包含私人数据或其他插件。默认仍须在控制台明确启用 QQ、选择人格和好友白名单。

NapCat 上游于 2026-11-13 撤下旧源码与发行下载。本仓库保留原许可证和可信文件清单摘要，**不再强制从失效地址下载组件或许可证**。源码构建者从本插件同一发行版的组件资产取得以下未经修改的官方原包，或使用自己保存的同版本原包：

- `NapCat.Shell.Windows.Node.zip`（4.18.41；校验值见 `engine.lock.json`）。
- `NapCat.Framework.zip`（4.18.41；校验值见 `desktop-engine.lock.json`）。

在 QQ 源码仓库执行，路径替换为原包实际位置：

```sh
npm run prepare:engine -- --archive "C:/Downloads/NapCat.Shell.Windows.Node.zip"
npm run prepare:desktop -- --archive "C:/Downloads/NapCat.Framework.zip"
npm run prepare:attach
npm run build -- --desktop
```

也可把这两个原包放进源码目录的 `.artifacts/vendor/`，再运行不带参数的 `prepare:engine` 和 `prepare:desktop`。这两步完全离线：缺包、错误版本、校验失败或异常路径会明确报错，保留先前准备好的组件，不自动改用其他镜像。原始组件保持原样，许可证保留完整原文，不导入运行中的账号配置。`prepare:attach` 仍按锁定摘要准备 Frida 17.24.0；其下载来源与 NapCat 无关，不自动升级。

普通 `npm run build` 生成外部 OneBot 模式包，不带 NapCat 或 Frida 原生绑定。普通包适合已有兼容 OneBot 服务的用户，不能代替完整桌面包。两种构建都在独占空目录中按源码依赖锁安装、核对白名单和摘要，再替换 `dist/qq/`；失败保留旧产物，普通重建会剔除先前桌面包的组件。构建只操作源码仓库的产物目录，不清理正式安装。

NapCat、QQ 和 Frida 各自沿用原许可，不按本仓库 AGPL 重新授权；NapCat 原许可包含非商业及再分发条件，详见 [第三方说明](THIRD_PARTY_NOTICES.md) 和 [原许可证](third-party/napcat/LICENSE)。桌面包及两个原包由统一发布流程审核后上传，源码 Git 仓库不收录第三方二进制、登录资料或组件压缩包。

旧版图库桥接的显式迁移脚本为 `scripts/gallery-migration.mjs`；先以不带 `--apply` 的方式预览，再按需要执行并保留备份。它不属于图库插件源码。

## 开发与构建

需要 Node.js 24.22.1 或更新版本、Git。宿主与插件采用同级独立仓库，宿主只用于公开类型与隔离测试，不复制进插件发行包。示例从同一个空父目录开始：

```sh
git clone https://github.com/iinukami/whalelife.git
cd whalelife
npm ci
cd ..
git clone https://github.com/iinukami/whalelife-plugin-gallery.git
cd whalelife-plugin-gallery
npm ci --ignore-scripts
npm run build
cd ..
git clone https://github.com/iinukami/whalelife-plugin-qq.git
cd whalelife-plugin-qq
npm ci --ignore-scripts
npm run build
npm run check
npm run prepare:attach
npm test
```

涉及 QQ 空间业务的联合回归放在 QQ 空间仓库；本项目覆盖 QQ 传输、引用诊断和图库服务接入。

将 `dist/qq/` 安装到宿主 `plugins/qq/`。首次安装后启动宿主；升级保留已有 `data/`，不要覆盖用户配置。

测试只使用模拟模型/平台和隔离目录，不使用个人账号或正式记忆。兼容测试覆盖当前宿主及既有最低宿主基线；运行测试前须保留宿主 Git 历史。

源码仓库不包含个人配置、凭据、会话记忆、日志、数据库、第三方运行包、node_modules 或构建产物。`.gitignore` 已排除这些目录；提交前仍需检查变更。

### 未完成表达与续发

普通文字中断后保留原话、原对象及逐段投递进度；通过 QQ 公开服务查询、明确续发或放弃。重连和插件重启不会自动补发，未知结果禁止重试。自主性可选接入后负责关联念头、判断继续时机；未接入时 QQ 普通收发不变。接口、临时正文边界及自主性接入流程见 [文字续发规范](TEXT-DELIVERY.md)。
